# approval-atlas

Static site exploring approved medicines across jurisdictions. Milestone 1 (EMA end to end) is done; **Milestone 2 is in progress** (phases below, each stops for review).

**Primary use case:** a phone lookup during conference talks/posters — type a drug, substance or condition, see EU approval status (what for, since when) and open the SmPC / EPAR. Charts are secondary. Keep first load small and the lookup usable offline.

## Scope
- M2 phases: (1) U.S. labels, filters + URL state, MeSH branches, ATC names, "Authorized now" view, authorized-over-time series — done; (1b) pocket lookup: search, medicine/substance cards with document links, condition results + timeline, regulatory-protection estimates, orphan exclusivity, offline — **current**; (2) ChEMBL enrichment: modality, mechanism, ATC cleanup, development-code synonyms in search; (3) regulatory events from EMA "procedural steps" PDFs + Lifecycle view; (4) MAH country (Union Register) + map tab. Hosting (public repo + GitHub Pages) after 1b.
- Do NOT start without being asked: FDA (Drugs@FDA / openFDA, Purple Book, Orange Book patents), cross-jurisdiction matching (INN/UNII), approval-lag views, other regulators, sponsor-name normalisation / `parent_company` (MAH data is structured so it can be added later), EU patent/SPC data (no open EU-wide source exists — show regulatory-protection estimates only, never call them patents).
- No backend, no database. Everything precomputed; filters run in the browser.

## Architecture decisions (with why)
- **Frontend: Vite + D3**, not Observable Framework. Framework is in maintenance mode (Observable, 2026-03-02: "not developing new features … recommend that users migrate to Notebook Kit"). Vanilla JS modules, no UI framework.
- **R pipeline is independent of the frontend**: writes files into `site/public/data/`; the frontend only reads them.
- **JSON, not Parquet**: small data; JSON needs no JS library. Revisit when events or FDA data make files large.
- **EMA column names kept verbatim** (British spelling). Columns we derive use U.S. spelling (`authorized_from`).
- **Approval date = `marketing_authorisation_date`.** `european_commission_decision_date` is the latest EC decision of any kind — never an approval date.
- **"Authorized now" tile vs over-time series**: tile = status `Authorised` with an approval date; series = dates (`authorized_from` ≤ d < `authorized_until`). Excluded from the series (`series_exclusion`): never-authorized statuses; ended status without an end date (88 on 2026-09-26 — prefer unknown to a guess); no approval date. The build fails if the tile ≠ the series' last point (snapshot date) and lists the rows.
- **Series computed twice on purpose**: R writes the unfiltered series; the browser recomputes it from per-product intervals so filters apply; a node test asserts they match.
- **Distinct active substances** = distinct normalised INN sets (`international_non_proprietary_name_common_name`, split on `;` and on ` / ` outside parentheses — e.g. "(rdESAT-6 / rCFP-10)" is one antigen — lower-case). Salts not merged.
- **Therapeutic-area broad category** = every top-level MeSH tree branch of the matched descriptor (NLM XML; exact heading → entry term → curated → unmatched). A medicine counts in every branch it touches. **Sub-areas** (user decision 2026-09-27: an expandable tree to MeSH level 3, branch › level 2 › level 3, counts at each level) = every level-2 and level-3 tree node above or at the matched descriptor (`ema_therapeutic_area_subtree.json`); a medicine counts once in every node it touches, so children do not add up to their parent; a term matched at a branch root ("Neoplasms") has no sub-area (the UI needs a "not more specific" row, as `atcExactCounts()`). Node names from the descriptor holding that tree number (unique at depths 2–3 in MeSH 2026; the build stops if that changes).
- **ATC**: EMA codes kept as published (`atc_code_human`; `atc_incomplete` when not a valid level-5 code: levels 1–4, or malformed like `LX1XX02`, `VO4D` with `atc_level` null). **`atc_code`** is the code the site should use: EMA's, or — when EMA's is incomplete or malformed — the code(s) in section 5.1 of the product information (SmPC) PDF (`atc_code_source` `ema_smpc`, user decision 2026-09-27, EMA reuse with credit; fass.se is not a source). An SmPC code completes EMA's when it is a valid code deeper than EMA's and fits it (starts with EMA's valid prefix, or WHO moved codes from under that prefix to it, e.g. EMA L01XE → SmPC L01EA01); an EMA level-5 code is never replaced. **Conflicts** (user decision 2026-09-27, phase 4d): when no SmPC code fits an incomplete (or malformed) EMA code, a deeper SmPC code that fits none of the product's EMA codes replaces it, marked `atc_code_conflict` true (5 on 2026-09-27: Yttriga V09 → V10X, Giapreza C09 → C01CX09, Vocabria J05AX → J05AJ04, Kerendia C09 → C03DA05, Libmeldy N07 → A16AB21); a shallower or equal misfit keeps EMA's (Pombiliti: EMA A16AB, SmPC A16A, rejected). Ambiguous SmPC codes are not used (several for one EMA code, or one conflicting code for several), so there stays one row per EMA code; the run summary lists conflicts, rejections and ambiguous codes separately. **Products with no EMA code** (missing or "Not yet assigned"; user decision 2026-09-27, phase 4d) get one row per distinct SmPC code (`source` `ema_smpc`, `atc_code_human` and `atc_level` null, `atc_incomplete` false, as `atc_level` and `atc_incomplete` describe EMA's published code only; the SmPC code may be at any level, so its own level tells whether it is complete; 16 products on 2026-09-27, all level 5). **Curated codes** (user decision 2026-09-27, phase 4e): `curated_atc_codes()` in `R/curated-atc-codes.R` (`ema_product_number`, `atc_code`, `evidence_source` `whocc_index` | `whocc_temporary` | `ema_smpc_text`, `evidence_url`, `checked_date`, `note`) holds 114 codes checked by hand for products whose code was still incomplete or missing: the proposals a second, independent check confirmed with high or medium confidence against saved ATC/DDD Index 2026 pages, the WHOCC temporary list (9 codes; `status` `temporary` in `atc_classes.json`, they can still change) or the SmPC text (all re-checked against that evidence); not the ones judged wrong (Tacquell, Imagify), doubtful (Rotashield) or low-confidence, rows without a proposal, or codes the product already had (Giapreza, Kerendia, Vocabria, Libmeldy, Ontilyv). A curated code is used (`atc_code_source` `curated`) only for an EMA code still incomplete after the SmPC step, under the rules for SmPC codes (valid, deeper, fits or replaces it as a marked conflict; never in place of an EMA level-5 or SmPC-completed code), and for a product without an EMA code whose SmPC gives no code at its final level: in place of an incomplete SmPC code under the same rules (the SmPC code in EMA's role; `source` then `curated`, the SmPC's verdict `curated`), or as its code when the SmPC gives none (none either way on 2026-09-28). The run summary lists the curated codes used and not used (with why: `smpc`, `ema_complete`, `rejected`, `not_in_data`) and the Authorised products without a complete code. On 2026-09-28: 109 used (9 conflicts, e.g. Aduhelm N07 → N06DX03, Natalizumab Elan Pharma L03AD → L04AG03), 5 not used as their SmPCs now give the same codes; 14 Authorised products left: Yttriga, EndolucinBeta, Lutetium (177Lu) chloride Billev, Theralugand, Ilumira (V10X), GalliaPharm, GalenVita (V09X), Lumeblue (V04CX), Strimvelis (L03AX), and Cuprymina, Vimkunya, Myqorzo, Boey, Wayrilz (no code anywhere). Every curated code has a WHO name in `atc_classes.json`. **Final level** (phase 4e): `atc_final_level` is true when `atc_code` is complete: a level-5 code, or a level-4 code WHO no longer subdivides, i.e. one the WHOCC alterations list moved level-5 codes under it up to ("ATC 5th levels deleted, all products classified on the 4th level"; only B03AC, iron parenteral preparations, 2014: Feraheme's EMA B03AC, Rienso's curated B03AC). The rule reads only the alterations list: were WHO to add level-5 codes under such a code again, the rule would need a check against the yearly lists. The frontend treats a code as incomplete when `atc_final_level` is false, not by its level. **Retired codes** (user decision 2026-09-27): `current_atc_code` = the code WHO moved a retired code to, transitively (L01XX28 → L01XE01 → L01EA01), from the WHOCC cumulative alterations list (level 5; split or partial moves keep the old code in use) or the curated table (`curated_retired_atc_levels` in `R/whocc.R`, a reason per row; its rows win over the list's): L01XC → L01F, as every L01XC code but L01XC04 (moved to L04AA34 in 2015) moved to L01F in 2022; L01XE → L01E, all in 2021; J07BX03 covid-19 vaccines → J07BN (level 4; user decision 2026-09-27: WHO deleted J07BX03 in 2023 without a successor, and COVID-19 vaccines are classified in J07BN); group and filter by `current_atc_code` (else `atc_code`), display the published code with its old name and "retired {year}, now {code}". Level names (user decision 2026-09-27, phase 4d: WHO's over ChEMBL's): the name alterations of the WHOCC yearly lists (sheet "ATC level name alterations"; this year's list, then last year's), then the curated WHO names (`curated_atc_name_corrections` in `R/whocc.R`: the 13 codes where ChEMBL_37's name differs from the ATC/DDD Index 2026 (version 2026-01-20), e.g. ChEMBL's "hemophilus" and "stems cells"; J07BX01 and V09IX15 are also renamed in the 2026 list; copied verbatim from the index pages and checked by hand), each replacing another name only where it differs (the run summary lists them); then ChEMBL's ATC table; then, for codes ChEMBL lacks, the new codes of the yearly lists (this year's first), single WHOCC index pages, the temporary list (`status` `temporary`), the alterations list (old level-5 names) and the curated archived names (all WHOCC names, verbatim in the data — a declared exception to the U.S.-spelling rule; Title Case is display-only). Display only: names in Title Case at every level, data verbatim (user decisions 2026-09-26 and 2026-09-27; see Frontend, `atcDisplayName()`); the footer credit stays short, README has the detail; interpretive risk under WHOCC's "no changes" term accepted.
- **Internal R package at repo root** (DESCRIPTION + one-line NAMESPACE, never built). `devtools::check()` is deliberately not a gate.
- **Hosting: GitHub Pages at approval-atlas.vrognas.com** — the repo is public (since creation; GitHub Free serves Pages only from public repos) and CI's `deploy` job publishes the site on every run on `main`. Needed for phone use. Outward changes (visibility, repo/Pages settings, DNS) only with the user's explicit OK. See "Trust baseline" and "Hosting".
- **Data committed ("git scraping")**: `site/public/data/` is tracked. CI's `commit-data` job commits it on scheduled/manual runs when anything other than `meta.json` and `ema_authorized_series.json` changed (both change daily with the snapshot date; they ride along with real changes). Gives a history of EMA changes and keeps the schedule active (60-day rule). Data files are regenerated by CI: after local pipeline runs, don't commit data by hand (`git restore site/public/data`) unless intended.

## Conventions
- **U.S. spelling in the UI.** Raw EMA values stay unchanged in data files; `site/src/labels.js` is the single map from raw values and UI copy to display text. A test rejects "authoris…" in UI text (function bodies included, so EMA field names such as `marketing_authorisation_date` belong in other modules, e.g. `statusDate()` in `approvals.js`).
- **No em-dashes in UI copy** (user decision 2026-09-27): commas, colons or parentheses instead; en-dash ranges ("1995–2026") stay. A test rejects U+2014 in `labels.js` values and `index.html`.
- **CSP-safe styling.** No `style=""` in HTML and no `.attr("style", …)`: CSS classes, or d3 `.style()` (CSSOM) for computed values such as bar widths.
- **Provenance**: every enriched value (ATC, therapeutic-area branch; later modality, events, MAH country) has a `source` column.
- **Caching**: external downloads live in `.cache/` (gitignored); per-source files in `.cache/downloads/<source>/`, refetched only when the source changes (MeSH: Last-Modified; ChEMBL: release). EMA medicines JSON: 24 h. Requests are throttled per host (`R/http.R`: `req_throttle(capacity = 1, …)`, no retry on 429).
- **Licensing**: code MIT. Data files: compilation CC BY-SA 4.0 (ChEMBL-derived values adapted from CC BY-SA 3.0); third-party values keep their own terms (see README). Credit every source in the footer and README.

## Data contract (`site/public/data/`)
JSON arrays of row objects; dates `"YYYY-MM-DD"` or `null`; flags `true/false`; missing `null` (never `""`); ids/codes strings; rows sorted (by `ema_product_number`, lookups then by value) so identical input gives identical output. Tables are written one record per line (`[`, rows joined by `,\n`, `]`), UTF-8, LF on every OS, so git diffs show changed rows; `meta.json` is pretty-printed.
- `ema_medicines.json` — one row per Human medicine; EMA columns minus `category`, the 3 vet-only columns and the 3 split fields; derived: `medicine_type` (Advanced therapy > Biosimilar > Generic > Other), `authorized_from`, `authorized_until`, `series_exclusion`, `substance_set_key`.
- `ema_medicine_therapeutic_areas.json` — `ema_product_number`, `therapeutic_area_mesh`.
- `ema_therapeutic_area_branches.json` — `therapeutic_area_mesh`, `mesh_descriptor_ui`, `mesh_descriptor_name`, `branch`, `branch_name`, `source`.
- `ema_therapeutic_area_subtree.json` (sub-areas; one row per term and level-2/3 tree node, distinct; sorted by term, then node) — `therapeutic_area_mesh`, `branch`, `node` (tree number), `level` (2 | 3), `parent` (the branch or level-2 node), `node_name` (descriptor name; null if MeSH has no record), `source` (the term's match source).
- `ema_medicine_active_substances.json` — `ema_product_number`, `active_substance` (EMA field).
- `ema_medicine_substances.json` — `ema_product_number`, `substance`, `substance_key` (from the INN field).
- `ema_medicine_atc_codes.json` (one row per product and EMA code; since phase 4d also one row per distinct SmPC code of a product without an EMA code (since phase 4e, when its SmPC gives none, per curated code; a curated code also replaces an SmPC code it completes when none of the product's SmPC codes is complete); SmPC codes not used stay in `ema_medicine_smpc_atc.json`; sorted by product, EMA code (null last), code) — `ema_product_number`, `atc_code_human`, `atc_level`, `atc_incomplete`, `source` as published (`source` "ema"; "Not yet assigned" dropped), or for a product without an EMA code `atc_code_human` null, `atc_level` null, `atc_incomplete` false and `source` "ema_smpc" (or "curated") (`atc_level` and `atc_incomplete` describe `atc_code_human` only; an SmPC-only code can be level 1–4); `atc_code` (the code to use, never null), `atc_code_source` (`ema` | `ema_smpc` | `curated`), `atc_code_conflict` (true when an SmPC or curated code replaced an incomplete EMA code it does not fit, else false), `atc_final_level` (phase 4e: true when `atc_code` is complete: level 5, or a level-4 code WHO no longer subdivides (B03AC); whether a code is incomplete is `!atc_final_level`), `atc_code_document_url`, `atc_code_document_date` (the product information used; for `curated` the evidence page (ATC/DDD Index page, temporary list or product information PDF) and the date it was checked; else null), `current_atc_code` (the code a retired `atc_code` moved to, else null), `current_atc_code_source` (`whocc_alterations` | `curated` | null). Row kinds (2026-09-28: 1,976 EMA + 126 completed and 5 conflicts from SmPCs + 100 completed and 9 conflicts from curated codes + 16 SmPC only = 2,232 rows): EMA's code `{"atc_code_human":"L04AB02","atc_level":5,"atc_incomplete":false,"source":"ema","atc_code":"L04AB02","atc_code_source":"ema","atc_code_conflict":false,"atc_final_level":true,…}`; completed (Aucatzyl) `{"atc_code_human":"L01XL","atc_level":4,"atc_incomplete":true,"source":"ema","atc_code":"L01XL12","atc_code_source":"ema_smpc","atc_code_conflict":false,"atc_final_level":true,"atc_code_document_url":"https://…aucatzyl-epar-product-information_en.pdf",…}`; conflict (Kerendia) `{"atc_code_human":"C09","atc_level":2,"atc_incomplete":true,"source":"ema","atc_code":"C03DA05","atc_code_source":"ema_smpc","atc_code_conflict":true,…}`; SmPC only (Entyvio) `{"atc_code_human":null,"atc_level":null,"atc_incomplete":false,"source":"ema_smpc","atc_code":"L04AG05","atc_code_source":"ema_smpc","atc_code_conflict":false,…}`; curated, temporary code (Tryngolza) `{"atc_code_human":"C10AX","atc_level":4,"atc_incomplete":true,"source":"ema","atc_code":"C10AX21","atc_code_source":"curated","atc_code_conflict":false,"atc_final_level":true,"atc_code_document_url":"https://atcddd.fhi.no/filearchive/documents/temporary_atc_and_ddd.xlsx","atc_code_document_date":"2026-09-27",…}`; curated conflict (Aduhelm) `{"atc_code_human":"N07",…,"atc_code":"N06DX03","atc_code_source":"curated","atc_code_conflict":true,"atc_final_level":true,"atc_code_document_url":"https://atcddd.fhi.no/atc_ddd_index/?code=N06DX&showdescription=no",…}`; complete at level 4 (Rienso) `{"atc_code_human":"B03","atc_level":2,"atc_incomplete":true,"source":"ema","atc_code":"B03AC","atc_code_source":"curated","atc_code_conflict":false,"atc_final_level":true,…}` and (Feraheme) `{"atc_code_human":"B03AC","atc_level":4,"atc_incomplete":true,"source":"ema","atc_code":"B03AC","atc_code_source":"ema","atc_final_level":true,…}`.
- `atc_classes.json` — `atc_code`, `level`, `name` (verbatim), `source` (`chembl_atc_class` | `whocc_updates` (a yearly list: new codes and name alterations) | `whocc_index` (index pages, and the curated WHO names) | `whocc_alterations` (old level-5 names) | `whocc_index_archived`), `status` (`current` | `retired` | `temporary`), `replaced_by` (current code of a retired one; null when deleted), `changed_year`, `status_source` (where a retired code's `status`, `replaced_by` and `changed_year` come from: `whocc_alterations` | `curated`; null otherwise; `source` names where the name comes from, e.g. ChEMBL for a code ChEMBL still lists), `source_url` (null for ChEMBL). WHOCC rows only for codes (and their prefixes) the data uses that ChEMBL lacks.
- `ema_medicine_smpc_atc.json` (SmPC checks: provenance, and the resume state CI commits; sorted by product, code) — `ema_product_number`, `document_url`, `document_last_updated_date`, `checked_date`, `reader_version` (phase 4e: the SmPC reader that made the check, `smpc_reader_version` in `R/smpc-atc.R`; checks written before versions read as 1), `smpc_status` (`code_found` | `incomplete` | `not_assigned` | `no_code` (no "ATC code" statement) | `no_text` | `not_found`), `atc_code` (one row per distinct code; null when none), `source` = `"ema_smpc"`. Codes as the SmPC gives them; validation against EMA's code happens at build time.
- `ema_authorized_series.json` — `date` (month-ends from 1995-01-31, then the snapshot date), `authorized_products`, `authorized_substances`.
- `meta.json` — `source_url`, `source_timestamp` (EMA verbatim), `snapshot_date`, `row_counts`, `attribution`, `sources` (name, url, version, retrieved, licence, attribution), `licence`.
- Phase 1b (lookup):
  - `ema_search_index.json` (small first-load index) — `ema_product_number`, `name_of_medicine`, `substances`, `substance_keys`, `active_substance`, `medicine_status`, `marketing_authorisation_date`, `medicine_type`, `orphan_medicine`.
  - `mesh_entry_terms.json` (folded entry term → descriptor, for EMA terms and their ancestors; sorted by `entry_term`) — `entry_term`, `mesh_descriptor_ui`.
  - `mesh_descriptor_areas.json` (descriptor → EMA terms in its subtree; sorted by `mesh_descriptor_ui`) — `mesh_descriptor_ui`, `mesh_descriptor_name`, `therapeutic_area_mesh`.
  - `ema_medicine_documents.json` (EPAR documents index: SmPC/product information, assessment reports, variation reports, summary, RMP summary, procedural steps) — `ema_product_number`, `document_type`, `title`, `url`, `first_published_date`, `last_updated_date`, `link_method` (`product_number` | `url_slug`), `source`.
  - `ema_medicine_protection.json` (regulatory-protection estimate: counted from the first central approval of the same substance set; 8 y data exclusivity, 10–11 y market protection) — `ema_product_number`, `basis` (`own` | `follows_reference` | `reference_not_found`), `reference_product_number`, `reference_name`, `counted_from`, `data_exclusivity_end`, `market_protection_end_min`, `market_protection_end_max`, `status` (`protected` | `ended` | `unclear`), `source` = `"estimate_from_ema_dates"`.
  - `ema_medicine_orphan_exclusivity.json` (Union Register orphan links; end = register EndDate or LinkDate + 10 y + extension) — `ema_product_number`, `eu_designation_number`, `condition`, `link_date`, `extension_months`, `exclusivity_end`, `end_source` (`register` | `computed`), `designation_status`, `source`.
  - `ema_medicine_register_status.json` (Union Register status per product; EMA status stays primary) — `ema_product_number`, `eu_number`, `register_status`, `register_last_decision_date`, `register_url`, `match_method` (`link` | `name` | `link_and_name`), `agrees_with_ema` (only register status "Active" counts as authorized; an unknown status stops the build, as the register is BETA), `source`.
  - Search folding (lower-case; one left-to-right pass `ae|oe` → `e`; hyphen-minus and U+2010–U+2015 → space; trim and collapse whitespace) is identical in R (`fold_search_text()`) and JS, guarded by a shared fixture used by both test suites.
- Lookup/index files (`ema_search_index`, `mesh_entry_terms`, `mesh_descriptor_areas`) have no `source` column: they index data, they don't enrich it.

## Frontend (phase 1b)
- URL keys: filters (phase 1; `atc` is a list since phase 4a, repeated keys like the other lists) plus `q` (free text), `med` (EMA product number), `sub` (substance_key), `cond` (MeSH descriptor UI). `view` (the removed "Authorized now" / "Approvals per year" tabs) is ignored without a note, so old links still load (`IGNORED_KEYS` in `url.js`). Therapeutic areas (phase 4f, one tree): `area` is one list holding MeSH branch codes (`C04`), tree numbers (`C04.588.180`) and EMA's terms (`Psoriasis`), combined with OR; there is no `branch` state key any more: a link's `branch` values load into `area` (so `?branch=C04&area=Psoriasis` still works and is rewritten to `?area=C04&area=Psoriasis`), an EMA term that is a branch or tree node itself loads as that key (`domain.areaCanonical`, `canonical()` in `areas.js`: `?area=Anemia` → `?area=C15.378.050`, `?area=Breast Neoplasms` → `C04.588.180`, `?area=Cancer` → `C04`; phase 4f review: so the tree shows one checked row; this widens such a link from the term alone to the term and everything under it, as MeSH means it), and an area under another selected one is dropped (`domain.areaAncestors`, as `toggleArea()`). Opening a card/result or a drug class uses pushState (back button works); filter edits use replaceState and announce the new headline.
- Loading order: meta + `ema_search_index` + `mesh_entry_terms` first (search usable immediately); everything else in the background; documents/protection/orphan files on first card open (substance, condition and indication-text result tables count as cards: their rows' PI/EPAR links and ATC codes); `ema_medicine_register_status` and `ema_medicine_documents` (the table's PI/EPAR links, added in place when it arrives) after the dashboard's first render (table marker, register note under the tiles).
- Offline: `site/public/sw.js` (production builds only) — cache-first for hashed `/assets/*` in a per-build cache (`approval-atlas-assets-<version>`, version stamped by `site/vite.config.js`; activate deletes older asset caches), network-first with cache fallback for pages, `/data/*.json`, manifest and icon in one cache kept across deploys (`approval-atlas-data`); never cross-origin (PDFs). Offline works after one online visit for what that visit loaded (card files and condition areas load on first use). `manifest.webmanifest` makes it installable.
- ATC names at every level display in Title Case (user decision 2026-09-27; data stays verbatim): `atcDisplayName()` in `labels.js`, used by `atcClassLabel()` ("{code} {Title Case name}", e.g. "L Antineoplastic and Immunomodulating Agents", "L04 Immunosuppressants"), `atcName()` and every aria-label built from them, so badges' hidden names and tooltips, ladders, ATC tree, breakdown, activity card, search suggestions, headline and sentence token all agree. Rules (tested on real names): minor words (and, or, and/or, nor, but, for, of, the, in, on, at, as, to, from, with, by, per, via, vs, a, an, excl., incl.) lower-case unless first or last ("Agents Acting on the Renin-Angiotensin System", "Arteriolar Smooth Muscle, Agents Acting On"), a lone capital "A" (vitamin) excepted; hyphen and slash parts each capitalized ("Musculo-Skeletal", "TNF-Alpha"); parts with digits ("GLP-1", "beta-1a" -> "Beta-1a", "B12") or inner capitals ("mTOR", "CoA", "ARBs") as written; in all-capitals names only the acronyms in `ATC_ACRONYMS` (scanned from `atc_classes.json`) stay capitals ("SURGICAL AIDS" -> "Surgical Aids"), in mixed-case names every all-capitals word is an acronym.

## Downloads and request budget (per daily run)
EMA (≤ 1 request / 2 s, shared throttle): medicines JSON — plain GET when the cached copy in `.cache/ema/` is > 24 h old (not persisted by CI); EPAR documents index (`documents-output-epar_documents_json-report_en.json`, 29 MB) and orphan designations (`medicines-output-orphan_designations-json-report_en.json` — note the hyphen before `json`) — conditional GET (ETag/Last-Modified) at most once per 20 h (just under the daily cron, as CI restores sidecars with old mtimes). EC (≤ 1 request / s, own throttle): Union Register `ods_products.json` (BETA; fields pinned), same rule. NLM MeSH and ChEMBL: only when changed. Caches: `.cache/downloads/{mesh,ema-documents,ema-orphans,union-register}/` with `source.json` sidecars; `.cache/downloads/chembl/` holds `status.json` and the release folder.
- **EMA product information PDFs (SmPC ATC codes)**: at most `APPROVAL_ATLAS_SMPC_BUDGET` per run (default 8; `0` = none), ≥ 20 s apart (on top of the EMA throttle), only for products whose EMA code is incomplete, malformed or missing, never checked or whose product information changed since (URL or `last_updated_date` in the documents index), or checked more than 180 days ago as `no_text` or `not_found` (in case that was passing), or checked by an older reader (`reader_version` below `smpc_reader_version`) that found no complete code (`no_code`, `incomplete`): Authorised first, then the newest documents. Bump `smpc_reader_version` when `extract_smpc_atc_codes()` learns to read more (version 2, phase 4e: "ATC" and "code" on two lines, "(ATC) code", a letter O for a zero in a digit position ("VO4CX"); its 19 re-checks ran on 2026-09-28 in two local runs). A 429, a response that is not a PDF (no `%PDF-` header, e.g. a firewall page with status 200) or any other failure ends the step with a warning (nothing recorded), never the build; a 404 is recorded as `not_found`. Each result is saved at once to `.cache/downloads/ema-smpc/checks.json` (seeded from the committed `ema_medicine_smpc_atc.json` when the cache is empty), so runs resume. PDFs go to a temp file and are deleted; PDF text needs `pdftools` (poppler; CI installs `libpoppler-cpp-dev` before setup-r). Local backfill: `APPROVAL_ATLAS_SMPC_BUDGET=25 Rscript scripts/run-pipeline.R`, repeated (about 10 min per 25); afterwards commit only `site/public/data/ema_medicine_smpc_atc.json` (CI seeds its checks from it) and restore the other data files (`git restore` them).
- **WHOCC** (`atcddd.fhi.no`, ≤ 1 request / 2 s, own realm): the yearly lists `atc_ddd_new_and_alterations_{year}_final.xlsx` of the index year (falls back to last year's on 404 in January) and of the year before (phase 4d: ChEMBL lags about a year, so both lists' new codes and name alterations are read, the newer first), and `temporary_atc_and_ddd.xlsx` — conditional GET at most once per 20 h; the cumulative ATC alterations page (no validators) — at most every 30 days; single ATC/DDD Index pages only for codes no other source names (the level-4 parent of a level-5 code), ≤ 10 per run, cached parsed in `.cache/downloads/whocc/index/{code}.json` for the index year (older pages rechecked at most monthly). Never crawl the index (it is sold, not published). WHOCC only names and maps codes, so it never stops the build: a failed download (network error, 429, 5xx, a removed file) uses the cached copy with a warning, or, without one, goes without that list (its names, moves and `meta.json` entry; the curated retired codes and names still apply); an index page that fails ends that run's lookups with a warning. A list that no longer parses still stops the build. Caches: `.cache/downloads/whocc/{updates,updates-previous,temporary,alterations,index}/`.

## EMA source facts (profiled 2026-09-26)
- Medicines JSON regenerated twice daily (06:00 / 18:00 Amsterdam); no ETag; If-Modified-Since works. `meta.timestamp` is Amsterdam local time labelled `Z` → use only its date part.
- EMA rate-limits: HTTP 429 after roughly 9–46 requests at 1–2 s spacing. Any per-product EMA fetching must be slow, budgeted and resumable.
- 39 columns, all strings, missing = `""`. 10 Yes/No flags. 11 `dd/mm/yyyy` date fields.
- Text: entities `&nbsp;` `&lt;` `&gt;` only (plus truncated `&nbsp`), literal U+00A0; no HTML tags. 122 indications have lossy `?` for ≥/≤ upstream.
- `;` fields: items contain commas (MeSH) — never split on comma. ATC: placeholders, L2–L4 codes, 2 malformed (`LX1XX02`, `VO4D`).
- Date gaps: 85 Withdrawn + Expired/Lapsed/Suspended rows without an end date; 6 Authorised without MA date; Xevudy end date < MA date; Enzepi's suspension date is really a withdrawal date.
- Reuse terms (EMA legal notice): acknowledge EMA as the source in every copy; no EMA logo; don't imply endorsement.
- IRIS-era procedure numbers (`VR/…`) have no II/IA/IB/X prefix.
- Product information PDFs (profiled 2026-09-27): ETag, `Last-Modified` = the documents index's `last_updated_date`; 0.5–3 MB, one PDF per product holding every SmPC (one per strength/form), Annex II and the labelling. Section 5.1: "Pharmacotherapeutic group: …, ATC code:" with the code often wrapped onto the next line ("L01XL12."); some say "not yet assigned" or give an incomplete code; "BATCH" contains "ATC" (match the label with a word boundary). Old PIs may be image-only (`no_text`).
- ATC gaps on 2026-09-27: 148 Authorised products with an incomplete code (36 at level 2, 21 at level 3, 91 at level 4) and 20 with none, all with product information; 419 products of any status, 214 with product information. EMA still uses retired codes (level 5, and L01XC/L01XE at level 4).

## Other sources
- MeSH: `https://nlmpubs.nlm.nih.gov/projects/mesh/MESH_FILES/xmlmesh/desc{YYYY}.gz` (ASCII discontinued 2026; year detected from the listing; new year ~December). NLM terms: acknowledge NLM, no endorsement, state the MeSH version.
- ChEMBL API `https://www.ebi.ac.uk/chembl/api/data/` (release from `status.json`; CHEMBL_37 on 2026-05-01). CC BY-SA 3.0; cite Mendez et al. 2019 (per ChEMBL's REQUIRED.ATTRIBUTION); keep ChEMBL IDs and show the release.
- WHO ATC names (via ChEMBL and the WHOCC site): © WHOCC — use requires reference to the WHOCC, no commercial distribution, no modification → verbatim, excluded from our licence ([terms](https://atcddd.fhi.no/copyright_disclaimer/)).
- WHOCC ATC/DDD Index `https://atcddd.fhi.no` (ISO-8859-1 HTML). Index pages (`/atc_ddd_index/?code={code}&showdescription=no`) have no validators (`Last-Modified` is always now); the ancestor path (`<b><a href="./?code=…">`) names every level above, the table lists the code or its children; a retired or unknown code has no row of its own (L01XE: ancestors only; L04AC28: empty), so the parser checks the code is present. "Last updated: 2026-01-20" = the index version. Yearly list (xlsx, ETag + Last-Modified; sheets "New ATC 5th levels", "New 3rd and 4th levels", "ATC level alterations", "ATC level name alterations" (code, previous name, "New ATC level name"), DDDs; same sheets in 2025 and 2026; names carry stray zero-width spaces); temporary list for next year's index (sheet names with stray blanks; codes may still change). Cumulative ATC alterations (`/atc_ddd_alterations__cumulative/atc_alterations/`, 2005–2026, ~355 rows: previous code, substance, new code or "deleted", year; footnotes as `<sup><a title>`: "Previous ATC level name: …", "Split of code …", "… only …" = the old code stays in use). ChEMBL lags the index by about a year (none of the 2026 changes are in ChEMBL_37) and spells some names differently; a one-off cross-check of every code the data uses against the index (2026-09-27; not repeated at runtime) found 13 names that differ and, besides B06C and L03AD (EMA codes WHO never had), no other problems.
- Internet Archive copies of the 2020 index (`web.archive.org/web/2020062…/https://www.whocc.no/atc_ddd_index/?code=L01XC|L01XE`): the only source for retired level-4 names; checked once by hand, never fetched at runtime.

## R conventions
- tidyverse / r-lib; always `package::function()`; no `library()`.
- `purrr::map()` + `purrr::list_rbind()`, never `map_dfr()`. `dplyr::case_when()` with `.default =`.
- `\(x)` only for one-liners, never in pipes; `function()` for anything multi-line.
- Descriptive unabbreviated names; small single-purpose functions; comments only for the "why".
- Loud failures via `cli::cli_abort()` listing offenders. Dependencies via renv (`snapshot.type = "explicit"`, `snapshot.dev = TRUE`; lockfile repo = dated Posit Package Manager snapshot; on CI `setup-r` overrides it with P3M `latest` Linux binaries — versions stay pinned by `renv.lock`).
- Tests: testthat 3e, fixtures of real records in `tests/testthat/fixtures/`; no network in tests. Coverage ≥ 80% overall, 100% for `R/validate-ema.R`.

Daily 06:37 UTC + manual + push to main. `build`: lint → R tests → pipeline on live data → `npm audit --audit-level=high --omit=dev` → npm test → build → Pages artifact + data artifact. Then, on `main` only: `deploy` (`pages: write`, `id-token: write`, environment `github-pages`) and, on scheduled/manual runs, `commit-data` (`contents: write`; see "Data committed"). One run at a time (`concurrency: pipeline`), 120 min timeout. `.cache/downloads` persists between runs via actions/cache (rolling key `downloads-v1-…`, saved even on failure; bump `v1` to force a refetch). Top-level `contents: read`, write grants per job only; no stored secrets. Every action pinned by full commit SHA (tag in a comment); `.github/dependabot.yml` updates actions and npm monthly. Failures email whoever last edited the cron line (enable GitHub Settings → Notifications → Actions → "Only notify for failed workflows").

## Trust baseline (with hosting; instead of ISO 27001 / SOC 2)
User wants credibility for a public site. ISO 27001 / SOC 2 certify organizations, not a static site with no backend or user data, so they are out of scope. Do instead:
- Security: Content-Security-Policy meta tag (GitHub Pages cannot set headers); no third-party scripts/fonts/trackers; Dependabot alerts + secret scanning + push protection; branch protection on `main`; CI actions pinned by SHA; `SECURITY.md`. Status of each: `docs/mvsp.md`.
- Privacy (GDPR): no cookies, no analytics; privacy note (GitHub logs IPs and page addresses, which hold the search, as host; offline mode stores only site data on the device).
- Accessibility: WCAG 2.2 AA target; axe-core in the headless check; manual keyboard pass.
- Intended use: informational only; not medical or legal advice; not a medical device; data may lag EMA.
- MVSP (mvsp.dev) self-assessment in `docs/mvsp.md` (control → status → evidence; review yearly): `SECURITY.md` with scope, safe harbor, GitHub private vulnerability reporting, fix within 90 days, notice within 72 h (1.1, 1.7, 3.4); data inventory (public regulatory data only, no personal data) + data-flow diagram (3.1, 3.2); Dependabot + `npm audit` gate (2.6); test forbidding `innerHTML`/`.html()` in `site/src` (2.5, 3.3); 2FA + branch protection (4.2); sub-processor list: GitHub (hosting, CI) (4.3); recovery = rebuild from repo + public sources (4.4). N/A: SSO, passwords, auth logging, physical access, pentest, training (no accounts, no backend, solo project).
- GitHub Pages cannot set response headers: no HSTS on custom domains, no `frame-ancestors`/X-Frame-Options (verified: jekyllrb.com on Pages sends none). Accepted risk (no logins or state-changing actions); alternatives are HSTS preload on the vrognas.com apex (Netlify) or hosting on Netlify with `_headers`.
