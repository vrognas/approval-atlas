# approval-atlas

Static site exploring approved medicines across jurisdictions. Milestone 1 (EMA end to end) is done; **Milestone 2 is in progress** (phases below, each stops for review).

**Primary use case:** a phone lookup during conference talks/posters — type a drug, substance or condition, see EU approval status (what for, since when) and open the SmPC / EPAR. Charts are secondary. Keep first load small and the lookup usable offline.

## Scope
- M2 phases: (1) U.S. labels, filters + URL state, MeSH branches, ATC names, "Authorized now" view, authorized-over-time series — done; (1b) pocket lookup: search, medicine/substance cards with document links, condition results + timeline, regulatory-protection estimates, orphan exclusivity, offline — **current**; (2) ChEMBL enrichment: modality, mechanism, ATC cleanup, development-code synonyms in search; (3) regulatory events from EMA "procedural steps" PDFs + Lifecycle view; (4) MAH country (Union Register) + map tab. Hosting (public repo + GitHub Pages) after 1b. Companies (holder names folded to companies and current-owner groups; the user asked 2026-09-28, see "Companies" below): part 1 (pipeline, GLEIF matching, review lists) done; part 2 (frontend: company pages, holder filter by group, monograms) next.
- Do NOT start without being asked: FDA (Drugs@FDA / openFDA, Purple Book, Orange Book patents), cross-jurisdiction matching (INN/UNII), approval-lag views, other regulators, ownership history (companies show the current owner only), EU patent/SPC data (no open EU-wide source exists — show regulatory-protection estimates only, never call them patents).
- No backend, no database. Everything precomputed; filters run in the browser.

## Architecture decisions (with why)
- **Frontend: Vite + D3**, not Observable Framework. Framework is in maintenance mode (Observable, 2026-03-02: "not developing new features … recommend that users migrate to Notebook Kit"). Vanilla JS modules, no UI framework.
- **R pipeline is independent of the frontend**: writes files into `site/public/data/`; the frontend only reads them.
- **JSON, not Parquet**: small data; JSON needs no JS library. Revisit when events or FDA data make files large.
- **EMA column names kept verbatim** (British spelling). Columns we derive use U.S. spelling (`authorized_from`).
- **Approval date = `marketing_authorisation_date`.** `european_commission_decision_date` is the latest EC decision of any kind — never an approval date.
- **"Authorized now" tile vs over-time series**: tile = status `Authorised` with an approval date; series = dates (`authorized_from` ≤ d < `authorized_until`). Excluded from the series (`series_exclusion`): never-authorized statuses; ended status without an end date (88 on 2026-09-26 — prefer unknown to a guess); no approval date. The build fails if the tile ≠ the series' last point (snapshot date) and lists the rows.
- **Series computed twice on purpose**: R writes the unfiltered series; the browser recomputes it from per-product intervals so filters apply; a node test asserts they match.
- **Distinct active substances** = distinct normalised INN sets (`international_non_proprietary_name_common_name`, or `active_substance` where the INN field repeats the medicine's name (Vysribli), split on `;` and on ` / ` outside parentheses — e.g. "(rdESAT-6 / rCFP-10)" is one antigen — lower-case). Salts not merged.
- **Regulatory-protection estimate** (`R/protection.R`; step 3 of the 2026-09-28 roadmap, scrutiny #6; estimates only, never "patent"): 8 + 2 (+ 1) years from the first central approval of the product's substance set. The set: the keys of `ema_medicine_substances.json` (the INN field's, or the `active_substance` field's where EMA's INN field repeats the medicine's name: `build_substances_table()`, `inn_names_medicine()`, name compared without its parentheses; Vysribli's "Vysribli" is denosumab in the substances table, search index and `substance_set_key` alike; only Vysribli and Garenoxacin mesylate on 2026-09-28, the latter unchanged), with keys joined by `curated_substance_equivalents()` (`R/curated-substances.R`: 33 pairs, each checked by hand against an EPAR page (active substance beside INN, "generic of"/"hybrid of"/"same as"), with a note; never a salt-stripping rule: fluticasone furoate/propionate and tenofovir disoproxil/alafenamide are different substances, a test guards them; sevelamer carbonate left out; transitive, so sitagliptin fumarate and sitagliptin hydrochloride monohydrate meet through sitagliptin; published as `ema_substance_equivalents.json`, pairs whose keys are not in the data warn and are left out). The first product (`first_products()`): among the set's non-generic, non-biosimilar products of the first approval's company group approved within 30 days of it, an authorised one, then the lowest product number (Humira over Trudexa, Plavix over Iscover a day earlier; the group limit keeps Ebixa (Lundbeck) the reference of Axura (Merz), Pritor (Bayer) of Micardis (Boehringer Ingelheim), Glustin (Takeda) of Actos (Cheplapharm)); `counted_from` is the first approval's date, as protection runs from the first authorisation (global marketing authorisation), not the named product's own (Humira's counts from Trudexa's 1 Sep 2003; the frontend must not show it as the named product's approval date). A generic or biosimilar follows the first product of its set as EMA spells it, else of the equivalent set (Inpremzia keeps Novo Nordisk's insulin, not Sanofi's Insuman; Dasatinib Accord Healthcare gets Sprycel). Another medicine counts from the equivalent set's first product; when that belongs to another company group (`ema_medicine_companies.json` `group_key`; groups are current owners, so licensees and copies of another company's medicine are flagged too, e.g. Roteas, Susvimo; curated copies are not: see below) and the first product of the medicine's own group came later (`own_counted_from` > `counted_from`), unless both estimates have ended, `basis` is `other_company_reference` with `own_reference_product_number` and `own_counted_from`; the market protection range then runs from the reference estimate's minimum to the own estimate's maximum and `status` is read from it, so it is `unclear` only where the two estimates' statuses differ (Opzelura: ended counted from Jakavi, protected from itself) and `protected` where both are (Qdenga, Spikevax: 12 on 2026-09-28; 6 on 2026-09-29, after the curated copies below: Kinpeygo and Ogluo are hybrids, and Sixmo and Cufence count from themselves, as Buvidal and Cuprior are hybrids). EMA's data flags only generics and biosimilars as copies. **Curated copies** (step 4, 2026-09-29; generalized from hybrids in the step 4 review): `curated_copy_medicines()` (`R/curated-copies.R`: `ema_product_number`, `copy_type` (`hybrid` | `generic` | `biosimilar`), `reference_product_number` (null when the reference medicine the EPAR names is authorised only nationally), `reference_name` (the reference as the page names it, national ones too: Hydrea, Subutex), `evidence_url` (the EPAR page whose overview says so), `evidence_quote` (verbatim, at most 20 words; it must name the copy type), `checked_date`, `note` (null unless needed: Riulvy's other substance, Lumeblue's former name, Okedi's reference form)): 41 rows, 39 hybrids plus a generic and a biosimilar whose EMA flags are false (Sugammadex Adroiq: Bridion, Tuznue: Herceptin), from the EPAR pages of the 56 `other_company_reference` products of 2026-09-28 (withdrawn ones without an overview on the page: their overview PDF) plus Riulvy, Colchicine Agepha Pharma, Cuprior, Buvidal, Okedi and Camcevi, and (owner request 2026-09-29, "complete the hybrid list") the 12 hybrids of the EPAR copy scan of every Authorised product counted as its own and protected (464 pages; 17 call the medicine a hybrid, the other 5 are PUMAs, below) and, in review, Nordimet (Lantarel FS), the one hybrid among the 44 counted as their own and unclear, all of nationally authorised references (Ledaga: Caryolysine, Nyxoid: Naloxon HCl B. A PUMA has basis `paediatric_use`: counted from its own approval (`reference_product_number` itself, `counted_from` its own date, never `other_company_reference`; Alkindi from 9 Feb 2018, not Plenadren's 2011; Slenyto not from Circadin's 2007), `copy_source` null, even where EMA flagged it generic or biosimilar; it stays another medicine's possible first product, and a curated copy of a PUMA follows the PUMA's own date. A curated copy is a follower (never another medicine's first product: Sixmo, counted from Buvidal before, counts from itself): with a central reference it follows it (`follows_reference`, `counted_from` = the reference's own `counted_from`, whatever its substances: Riulvy (tegomil fumarate) follows Tecfidera (dimethyl fumarate); 12 on 2026-09-29, e.g. Liraglutide STADA: Victoza, Ablymico: Saxenda, Armisarte: Alimta, Sugammadex Adroiq: Bridion), with a national one it has `reference_not_found` (no dates, `unclear`; 29 on 2026-09-29, e.g. Xromi: Hydrea, Buvidal: Subutex, Colchicine Agepha Pharma: Colchicine Tiofarma). The frontend must not describe a curated copy's `counted_from` as the first approval of its own substance (Riulvy's is Tecfidera's, dimethyl fumarate), but as its reference medicine's. Malformed rows (product numbers, a copy type the quote does not name, a reference that is the medicine itself or another curated copy, no reference name, evidence) stop the build; rows whose medicine or central reference is not in the data (dated) warn and are left out. Still counted as medicines of their own: informed-consent and duplicate copies (Roteas: Lixiana, Senstend: Fortacin) and copies not yet checked (README caveat); `scripts/scan-epar-copies.R` lists candidates (see "Downloads"). The run summary lists every product whose status differs from the file the last run wrote (`report_protection_changes()`).
- **Therapeutic-area broad category** = every top-level MeSH tree branch of the matched descriptor (NLM XML; exact heading → entry term → curated → unmatched). A medicine counts in every branch it touches. **Sub-areas** (user decision 2026-09-27: an expandable tree to MeSH level 3, branch › level 2 › level 3, counts at each level) = every level-2 and level-3 tree node above or at the matched descriptor (`ema_therapeutic_area_subtree.json`); a medicine counts once in every node it touches, so children do not add up to their parent; a term matched at a branch root ("Neoplasms") has no sub-area (the UI needs a "not more specific" row, as `atcExactCounts()`). Node names from the descriptor holding that tree number (unique at depths 2–3 in MeSH 2026; the build stops if that changes).
- **ATC**: EMA codes kept as published (`atc_code_human`; `atc_incomplete` when not a valid level-5 code: levels 1–4, or malformed like `LX1XX02`, `VO4D` with `atc_level` null). **`atc_code`** is the code the site should use: EMA's, or — when EMA's is incomplete or malformed — the code(s) in section 5.1 of the product information (SmPC) PDF (`atc_code_source` `ema_smpc`, user decision 2026-09-27, EMA reuse with credit; fass.se is not a source). An SmPC code completes EMA's when it is a valid code deeper than EMA's and fits it (starts with EMA's valid prefix, or WHO moved codes from under that prefix to it, e.g. EMA L01XE → SmPC L01EA01); an EMA level-5 code is never replaced. **Conflicts** (user decision 2026-09-27, phase 4d): when no SmPC code fits an incomplete (or malformed) EMA code, a deeper SmPC code that fits none of the product's EMA codes replaces it, marked `atc_code_conflict` true (5 on 2026-09-27: Yttriga V09 → V10X, Giapreza C09 → C01CX09, Vocabria J05AX → J05AJ04, Kerendia C09 → C03DA05, Libmeldy N07 → A16AB21); a shallower or equal misfit keeps EMA's (Pombiliti: EMA A16AB, SmPC A16A, rejected). Ambiguous SmPC codes are not used (several for one EMA code, or one conflicting code for several), so there stays one row per EMA code; the run summary lists conflicts, rejections and ambiguous codes separately. **Products with no EMA code** (missing or "Not yet assigned"; user decision 2026-09-27, phase 4d) get one row per distinct SmPC code (`source` `ema_smpc`, `atc_code_human` and `atc_level` null, `atc_incomplete` false, as `atc_level` and `atc_incomplete` describe EMA's published code only; the SmPC code may be at any level, so its own level tells whether it is complete; 16 products on 2026-09-27, all level 5). **Curated codes** (user decision 2026-09-27, phase 4e): `curated_atc_codes()` in `R/curated-atc-codes.R` (`ema_product_number`, `atc_code`, `evidence_source` `whocc_index` | `whocc_temporary` | `ema_smpc_text`, `evidence_url`, `checked_date`, `note`) holds 114 codes checked by hand for products whose code was still incomplete or missing: the proposals a second, independent check confirmed with high or medium confidence against saved ATC/DDD Index 2026 pages, the WHOCC temporary list (9 codes; `status` `temporary` in `atc_classes.json`, they can still change) or the SmPC text (all re-checked against that evidence); not the ones judged wrong (Tacquell, Imagify), doubtful (Rotashield) or low-confidence, rows without a proposal, or codes the product already had (Giapreza, Kerendia, Vocabria, Libmeldy, Ontilyv). A curated code is used (`atc_code_source` `curated`) only for an EMA code still incomplete after the SmPC step, i.e. one the SmPC step left as it was or gave a code not at its final level (see "Final level" below: level 5, or a level-4 code WHO no longer subdivides), judged against EMA's published code under the rules for SmPC codes (valid, deeper, fits or replaces it as a marked conflict; never in place of an EMA level-5 code or an SmPC code at its final level); such an SmPC code then gives way to the curated code (the SmPC's verdict `curated`) and stays where none is used (Strimvelis: EMA L03, SmPC L03AX, no curated code). LeukoScan (2026-09-29): EMA publishes the malformed VO4D, its SmPC reads V04D, which is no WHO class (WHO's V04 has V04B and V04C), and the curated V09HA04 (technetium (99mTc) sulesomab, ATC/DDD Index 2026) replaces it, no conflict, as it fits VO4D's valid start V (a malformed code keeps its valid start only; V09HA04 would not fit the SmPC's V04D, but the conflict flag is about EMA's code). And a curated code is used for a product without an EMA code whose SmPC gives no code at its final level: in place of an incomplete SmPC code under the same rules (the SmPC code in EMA's role; `source` then `curated`, the SmPC's verdict `curated`), or as its code when the SmPC gives none (none either way on 2026-09-28). The run summary lists the curated codes used and not used (with why: `smpc`, the product's SmPC code is at its final level; `ema_complete`; `rejected`, including one not used against an SmPC code not at its final level; `not_in_data`) and the Authorised products without a complete code. On 2026-09-29: 88 used (9 conflicts, e.g. Aduhelm N07 → N06DX03, Natalizumab Elan Pharma L03AD → L04AG03; LeukoScan's V09HA04 again, as on 2026-09-28, after the first check of its SmPC had displaced it), 26 not used as their SmPCs now give the same code (22) or the retired code WHO moved to it (4: Incivo J05AE11 → J05AP02, Victrelis J05AE12 → J05AP03, Portrazza L01XC22 → L01FE03, Lumoxiti L01XC34 → L01FB02) (2026-09-28: 109 used, 5 not used); 14 Authorised products left: Yttriga, EndolucinBeta, Lutetium (177Lu) chloride Billev, Theralugand, Ilumira (V10X), GalliaPharm, GalenVita (V09X), Lumeblue (V04CX), Strimvelis (L03AX), and Cuprymina, Vimkunya, Myqorzo, Boey, Wayrilz (no code anywhere). Every curated code has a WHO name in `atc_classes.json`. **Final level** (phase 4e): `atc_final_level` is true when `atc_code` is complete: a level-5 code, or a level-4 code WHO no longer subdivides, i.e. one the WHOCC alterations list moved level-5 codes under it up to ("ATC 5th levels deleted, all products classified on the 4th level"; only B03AC, iron parenteral preparations, 2014: Feraheme's EMA B03AC, Rienso's curated B03AC). The frontend treats a code as incomplete when `atc_final_level` is false, not by its level. **Retired codes** (user decision 2026-09-27): `current_atc_code` = the code WHO moved a retired code to, transitively (L01XX28 → L01XE01 → L01EA01), from the WHOCC cumulative alterations list (level 5; split or partial moves keep the old code in use) or the curated table (`curated_retired_atc_levels` in `R/whocc.R`, a reason per row; its rows win over the list's): L01XC → L01F, as every L01XC code but L01XC04 (moved to L04AA34 in 2015) moved to L01F in 2022; L01XE → L01E, all in 2021; J07BX03 covid-19 vaccines → J07BN (level 4; user decision 2026-09-27: WHO deleted J07BX03 in 2023 without a successor, and COVID-19 vaccines are classified in J07BN); group and filter by `current_atc_code` (else `atc_code`), display the published code with its old name and "retired {year}, now {code}". Level names (user decision 2026-09-27, phase 4d: WHO's over ChEMBL's): the name alterations of the WHOCC yearly lists (sheet "ATC level name alterations"; this year's list, then last year's), then the curated WHO names (`curated_atc_name_corrections` in `R/whocc.R`: the 13 codes where ChEMBL_37's name differs from the ATC/DDD Index 2026 (version 2026-01-20), e.g. ChEMBL's "hemophilus" and "stems cells"; J07BX01 and V09IX15 are also renamed in the 2026 list; copied verbatim from the index pages and checked by hand), each replacing another name only where it differs (the run summary lists them); then ChEMBL's ATC table; then, for codes ChEMBL lacks, the new codes of the yearly lists (this year's first), single WHOCC index pages, the temporary list (`status` `temporary`), the alterations list (old level-5 names) and the curated archived names (all WHOCC names, verbatim in the data — a declared exception to the U.S.-spelling rule; Title Case is display-only). Display only: names in Title Case at every level, data verbatim (user decisions 2026-09-26 and 2026-09-27; see Frontend, `atcDisplayName()`); the footer credit stays short, README has the detail; interpretive risk under WHOCC's "no changes" term accepted.
- **ATC class explanations** (owner decisions 2026-09-29; `R/atc-explanations.R`): a plain-language explanation of what each ATC class at levels 1–4 the data uses is for, not a restatement of WHO's name (543 on 2026-09-29: 14 at level 1, 72 at 2, 138 at 3, 319 at 4; level 5 has none, its substance's name says what it is). Our own texts, written and reviewed by hand in two rounds (`.remember/atc-explanations/review.md`), in the committed input `data-raw/atc-class-explanations.json`; WHO's codes and names stay WHO's (`atc_classes.json`, excluded from our licence), the explanations are ours (part of the CC BY-SA 4.0 compilation; credited so in the footer, README and `meta.json`). **Owner rule** (standing): each text is generic to its WHO class, never naming or describing the medicines in it now (no brand; a substance only where the class's WHO name holds it or it is what the class acts on, e.g. "testosterone" for anti-androgens), so a class never needs rechecking when a medicine joins. The texts are final: never edit them; report one that seems wrong to the owner. The pipeline (`read_atc_explanations()`, `check_atc_explanations()`, `build_atc_explanations_table()`) stops the build (`cli::cli_abort()` listing offenders) on a code that is not an ATC class at levels 1–4, a repeated code, a level that is not the code's, an empty text, a text over 20 words, an em-dash, a text naming a medicine name, substance key or EMA active-substance text of the data (`atc_explanation_terms()`; the texts catch salts and spellings the keys lack: Neoatricon's key is "dopamine hydrochloride", its text "Dopamine") (whole words, case-insensitive: `fold_explanation_words()`) unless it is in the class's WHO name or on `atc_explanation_allowed_words()` in the classes named there (each word with its `codes`, the classes it is allowed in and their descendants, and its reason; review of the explanations: a word allowed everywhere would let "testosterone" pass in G03B, the androgens, where it names a medicine; derived by running the check on the texts of 2026-09-29: "amino acids" in A16AX (it names what it is not, its sibling A16AA's WHO name), "angiotensin ii" in C09A (what ACE inhibitors stop the body making), "dopamine" in C01CA, N04, N05A and N06BA (the messenger and receptor type they act on), "levodopa" in N04BA (its "dopa" by its INN), "parathyroid hormone" in H05B (what it lowers), "testosterone" in L02AE and L02B (what they act on); add a word or class only with its reason; a test checks every word is needed in every class listed). Other names of a substance (search.js `SPELLING_VARIANTS`, e.g. adrenaline for epinephrine, which 14 texts use as a receptor and messenger name) are not checked, a checked date that is no date or no source. It warns (the rows are left out) about classes the data uses without an explanation (one WHO does not name says "(no WHO name)": a new class needs a new text under the owner rule) and about explanations of classes the data no longer uses. The classes in use: every level 1–4 prefix of the code each ATC row is shown by, `current_atc_code` ?? `atc_code`, valid codes only (`atc_explained_classes_in_use()`), as the frontend's `atcCode()`; the prefixes of a retired code no row is shown by (L01XC) are not in use (none on 2026-09-29, every class in use has one).
- **Companies** (user decisions 2026-09-28; `R/companies.R`, `R/curated-companies.R`, `R/gleif.R`): two levels. A **company** folds spelling and legal-entity variants of holder names (rules at the "k2" tier: diacritics with German umlauts spelled out, "&"/"+" as "and", address tails ("c/o …", "… at Fieldfisher LLP") and parenthesised parts dropped, legal forms at the end (and "N.V." at the start), place and role words anywhere (Ireland, Europe, International, Registration, Holding, branch…); generic words such as "pharma" stay, as stripping them broke names; `company_match_key()`, plus curated aliases for renames and misspellings; an alias whose target has the same key only fixes the name, e.g. EMA's "Theravance Biopharma Ireland Umited" ("Umited" folds as a legal form) → "…Limited": it is no link of an alias chain, and a name that is an alias's (folded) is never the company's name); key `c.<slug>`, name = not a curated alias (a misspelling or an old name) while the alias's target or another spelling is at hand, then the spelling of most medicines, then EMA's; an address tail dropped ("Kamada BioPharma Limited"). ## Conventions
- **U.S. spelling in the UI.** Raw EMA values stay unchanged in data files; `site/src/labels.js` is the single map from raw values and UI copy to display text. A test rejects "authoris…" in UI text (function bodies included, so EMA field names such as `marketing_authorisation_date` belong in other modules, e.g. `statusDate()` in `approvals.js`).
- **No em-dashes in UI copy** (user decision 2026-09-27): commas, colons or parentheses instead; en-dash ranges ("1995–2026") stay. A test rejects U+2014 in `labels.js` values and `index.html`.
- **CSP-safe styling.** No `style=""` in HTML and no `.attr("style", …)`: CSS classes, or d3 `.style()` (CSSOM) for computed values such as bar widths.
- **Provenance**: every enriched value (ATC, therapeutic-area branch, company and group, modality (with its `rule`), ATC class explanation; later events) has a `source` column (`companies.json`: a `sources` list per row).
- **Caching**: external downloads live in `.cache/` (gitignored); per-source files in `.cache/downloads/<source>/`, refetched only when the source changes (MeSH: Last-Modified; ChEMBL: release). EMA medicines JSON: 24 h. Requests are throttled per host (`R/http.R`: `req_throttle(capacity = 1, …)`, no retry on 429).
- **Licensing**: code MIT. Data files: compilation CC BY-SA 4.0 (ChEMBL-derived values adapted from CC BY-SA 3.0); third-party values keep their own terms (see README; GLEIF LEI data CC0, credited anyway, never implying GLEIF provides the site). Our own texts (the ATC class explanations, curated notes) are part of the compilation; WHO's ATC codes and names are not, and the credits say which is whose. Credit every source in the footer and README.

## Downloads and request budget (per daily run)
EMA (≤ 1 request / 2 s, shared throttle): medicines JSON — plain GET when the cached copy in `.cache/ema/` is > 24 h old (not persisted by CI); EPAR documents index (`documents-output-epar_documents_json-report_en.json`, 29 MB) and orphan designations (`medicines-output-orphan_designations-json-report_en.json` — note the hyphen before `json`) — conditional GET (ETag/Last-Modified) at most once per 20 h (just under the daily cron, as CI restores sidecars with old mtimes). EC (≤ 1 request / s, own throttle): Union Register `ods_products.json` (BETA; fields pinned), same rule. NLM MeSH and ChEMBL: only when changed. Caches: `.cache/downloads/{mesh,ema-documents,ema-orphans,union-register}/` with `source.json` sidecars; `.cache/downloads/chembl/` holds `status.json` and the release folder.
- **EMA product information PDFs (SmPC ATC codes)**: at most `APPROVAL_ATLAS_SMPC_BUDGET` per run (default 8; `0` = none), ≥ 20 s apart (on top of the EMA throttle), only for products whose EMA code is incomplete, malformed or missing, never checked or whose product information changed since (URL or `last_updated_date` in the documents index), or checked more than 180 days ago as `no_text` or `not_found` (in case that was passing), or checked by an older reader (`reader_version` below `smpc_reader_version`) that found no complete code (`no_code`, `incomplete`): Authorised first, then the newest documents. Bump `smpc_reader_version` when `extract_smpc_atc_codes()` learns to read more (version 2, phase 4e: "ATC" and "code" on two lines, "(ATC) code", a letter O for a zero in a digit position ("VO4CX"); its 19 re-checks ran on 2026-09-28 in two local runs). A 429, a response that is not a PDF (no `%PDF-` header, e.g. a firewall page with status 200) or any other failure ends the step with a warning (nothing recorded), never the build; a 404 is recorded as `not_found`. Each result is saved at once to `.cache/downloads/ema-smpc/checks.json` (seeded from the committed `ema_medicine_smpc_atc.json` when the cache is empty), so runs resume. PDFs go to a temp file and are deleted; PDF text needs `pdftools` (poppler; CI installs `libpoppler-cpp-dev` before setup-r). Local backfill: `APPROVAL_ATLAS_SMPC_BUDGET=25 Rscript scripts/run-pipeline.R`, repeated (about 10 min per 25); afterwards commit only `site/public/data/ema_medicine_smpc_atc.json` (CI seeds its checks from it) and restore the other data files (`git restore` them).
- **GLEIF** (`api.gleif.org`, on demand only, never in CI or the daily pipeline): `Rscript scripts/match-gleif.R` after a pipeline run (it reads the cached EMA and Union Register files), ≥ 1.2 s apart (GLEIF allows 60 a minute), own realm, no retry on 429, at most 170 requests per run (about 150 for a full run: names 10 per request with `include=ultimate-parent`; misses by the name without legal form in the holder's country; brand words among group top entities (`ultimateChildCount>=1`, hints only); parents' records by LEI, 100 per request). Spaces must be `%20` (a `+` silently finds nothing). Responses cached by URL in `.cache/downloads/gleif/` (`index.json`, with each URL's file and fetch date (an entry without a date is dated by its file), and `responses/`), so a rerun resumes; a response older than 30 days is fetched again (`run_gleif_matching(max_age_days =)`, `Inf` never), and the matches (and `meta.json`) carry the oldest response date used, not the run date. Commit `data-raw/gleif-holder-matches.json`; review matches below 0.95 before setting `reviewed`.
- **ChEMBL molecules** (modality, `R/chembl-molecules.R`; `www.ebi.ac.uk/chembl/api/data/molecule.json`, on demand only, never in CI or the daily pipeline): `Rscript scripts/match-chembl-modality.R` after a pipeline run (`run_chembl_matching()`: every key the run classifies, read from its `site/public/data` files through `modality_inputs()`). Per key, stop at the first hit: `pref_name__iexact`, then `molecule_synonyms__molecule_synonym__iexact` (`limit=50`, `only=` molecule_chembl_id, pref_name, molecule_type, structure_type, max_phase, biotherapeutic, molecule_hierarchy, atc_classifications, molecule_synonyms), then the same for its alternates in order (the one other active substance of its medicines, curated equivalent keys, the name before a comma, "hydrogen carbonate" → "bicarbonate", the WHO name of its medicines' one level-5 non-vaccine code); pick: synonym type INN < EMA < BAN/USAN/JAN/USP < FDA/ATC/BNF < MERCK_INDEX < OTHER < TRADE_NAME < RESEARCH_CODE, then parent before salt, higher `max_phase`, lower ChEMBL ID (all candidates kept when more than one); the parents of salt matches by `molecule_chembl_id__in`, 50 per request; for an unmatched key that is no vaccine description, its variants (spelling, qualifier, salt, isotope; at most 8, the first that finds any) and then `pref_name__istartswith` "{key} " (keys of 6+ letters) as candidates for review. 1.1 s apart (`throttled_request(realm = "chembl")`), no retry on 429 (the run stops, the cache kept), at most 2,000 requests per run. Responses cached by URL in `.cache/downloads/chembl-molecules/<release>/` (`index.json` URL → file and fetch date, `responses/`), never refetched within a release, so a rerun resumes and needs none; a new ChEMBL release starts a new folder. The prototype's 1,648 responses (2026-09-28) were converted into this cache (URLs rebuilt with the canonical fields; its matches, `.remember/modality/chembl-matches.json`, seeded the file), so the first R run needed 170 requests (the R1/R2 keys and alternates); the pipeline warns when the file's release differs from ChEMBL's (`status.json`) and lists keys missing from it. Commit `data-raw/chembl-substance-matches.json`; review ambiguous rows and variant candidates before setting `reviewed` (with `molecule_chembl_id` filled by hand for a variant).
- **EMA EPAR pages, copy scan** (step 4 review; on demand only, never in CI or the daily pipeline; `R/epar-copy-scan.R`): `Rscript scripts/scan-epar-copies.R` after a pipeline run (it reads `ema_medicine_protection.json` and `ema_medicines.json` in `site/public/data`; changes no data): the EPAR page (`medicine_url`) of each Authorised product with basis `own` and status `protected` or `unclear` (not `ended`) not yet curated or checked, by product number (464 protected and 44 unclear on 2026-09-29); at most `APPROVAL_ATLAS_EPAR_BUDGET` pages per run (default 30, about 10 min), ≥ 20 s apart on top of the EMA throttle. A 429, another failure or a page without the medicine's name (a firewall page with status 200) ends the run with a warning; a 404 is recorded as `not_found`. Each result is saved at once to `.cache/downloads/ema-epar-copies/checks.json` (not committed), so reruns resume. It lists the pages with a paragraph saying "hybrid medicine", "generic medicine" or "biosimilar medicine" or "biosimilar medicinal product" (not the "Generic and hybrid medicines" link), with that paragraph: check each by hand before adding a row to `curated_copy_medicines()`.
- **WHOCC** (`atcddd.fhi.no`, ≤ 1 request / 2 s, own realm): the yearly lists `atc_ddd_new_and_alterations_{year}_final.xlsx` of the index year (falls back to last year's on 404 in January) and of the year before (phase 4d: ChEMBL lags about a year, so both lists' new codes and name alterations are read, the newer first), and `temporary_atc_and_ddd.xlsx` — conditional GET at most once per 20 h; the cumulative ATC alterations page (no validators) — at most every 30 days; single ATC/DDD Index pages only for codes no other source names (the level-4 parent of a level-5 code), ≤ 10 per run, cached parsed in `.cache/downloads/whocc/index/{code}.json` for the index year (older pages rechecked at most monthly). Never crawl the index (it is sold, not published). WHOCC only names and maps codes, so it never stops the build: a failed download (network error, 429, 5xx, a removed file) uses the cached copy with a warning, or, without one, goes without that list (its names, moves and `meta.json` entry; the curated retired codes and names still apply); an index page that fails ends that run's lookups with a warning. A list that no longer parses still stops the build. Caches: `.cache/downloads/whocc/{updates,updates-previous,temporary,alterations,index}/`.

## EMA source facts (profiled 2026-09-26)
- Medicines JSON regenerated twice daily (06:00 / 18:00 Amsterdam); no ETag; If-Modified-Since works. `meta.timestamp` is Amsterdam local time labelled `Z` → use only its date part.
- EMA rate-limits: HTTP 429 after roughly 9–46 requests at 1–2 s spacing. Any per-product EMA fetching must be slow, budgeted and resumable.
- 39 columns, all strings, missing = `""`. 10 Yes/No flags. 11 `dd/mm/yyyy` date fields.
- Text: entities `&nbsp;` `&lt;` `&gt;` only (plus truncated `&nbsp`), literal U+00A0; no HTML tags. 122 indications have lossy `?` for ≥/≤ upstream.
- `;` fields: items contain commas (MeSH) — never split on comma. ATC: placeholders, L2–L4 codes, 2 malformed (`LX1XX02`, `VO4D`).
- Date gaps: 85 Withdrawn + Expired/Lapsed/Suspended rows without an end date; 6 Authorised without MA date; Xevudy end date < MA date; Enzepi's suspension date is really a withdrawal date.
- Reuse terms (EMA legal notice): acknowledge EMA as the source in every copy; no EMA logo; don't imply endorsement.
- IRIS-era procedure numbers (`VR/…`) have no II/IA/IB/X prefix.
- Product information PDFs (profiled 2026-09-27): ETag, `Last-Modified` = the documents index's `last_updated_date`; 0.5–3 MB, one PDF per product holding every SmPC (one per strength/form), Annex II and the labelling. Section 5.1: "Pharmacotherapeutic group: …, ATC code:" with the code often wrapped onto the next line ("L01XL12."); some say "not yet assigned" or give an incomplete code; "BATCH" contains "ATC" (match the label with a word boundary). Old PIs may be image-only (`no_text`).
- ATC gaps on 2026-09-27: 148 Authorised products with an incomplete code (36 at level 2, 21 at level 3, 91 at level 4) and 20 with none, all with product information; 419 products of any status, 214 with product information. EMA still uses retired codes (level 5, and L01XC/L01XE at level 4).

## Other sources
- MeSH: `https://nlmpubs.nlm.nih.gov/projects/mesh/MESH_FILES/xmlmesh/desc{YYYY}.gz` (ASCII discontinued 2026; year detected from the listing; new year ~December). NLM terms: acknowledge NLM, no endorsement, state the MeSH version.
- ChEMBL API `https://www.ebi.ac.uk/chembl/api/data/` (release from `status.json`; CHEMBL_37 on 2026-05-01). CC BY-SA 3.0; cite Mendez et al. 2019 (per ChEMBL's REQUIRED.ATTRIBUTION); keep ChEMBL IDs and show the release.
- WHO ATC names (via ChEMBL and the WHOCC site): © WHOCC — use requires reference to the WHOCC, no commercial distribution, no modification → verbatim, excluded from our licence ([terms](https://atcddd.fhi.no/copyright_disclaimer/)).
- WHOCC ATC/DDD Index `https://atcddd.fhi.no` (ISO-8859-1 HTML). Index pages (`/atc_ddd_index/?code={code}&showdescription=no`) have no validators (`Last-Modified` is always now); the ancestor path (`<b><a href="./?code=…">`) names every level above, the table lists the code or its children; a retired or unknown code has no row of its own (L01XE: ancestors only; L04AC28: empty), so the parser checks the code is present. "Last updated: 2026-01-20" = the index version. Yearly list (xlsx, ETag + Last-Modified; sheets "New ATC 5th levels", "New 3rd and 4th levels", "ATC level alterations", "ATC level name alterations" (code, previous name, "New ATC level name"), DDDs; same sheets in 2025 and 2026; names carry stray zero-width spaces); temporary list for next year's index (sheet names with stray blanks; codes may still change). Cumulative ATC alterations (`/atc_ddd_alterations__cumulative/atc_alterations/`, 2005–2026, ~355 rows: previous code, substance, new code or "deleted", year; footnotes as `<sup><a title>`: "Previous ATC level name: …", "Split of code …", "… only …" = the old code stays in use). ChEMBL lags the index by about a year (none of the 2026 changes are in ChEMBL_37) and spells some names differently; a one-off cross-check of every code the data uses against the index (2026-09-27; not repeated at runtime) found 13 names that differ and, besides B06C and L03AD (EMA codes WHO never had), no other problems.
- GLEIF LEI records (API `https://api.gleif.org/api/v1/lei-records`, profiled 2026-09-28): CC0; `filter[entity.names]` is a case-insensitive "contains" over legal, other and transliterated names, commas separate names (so a name's own commas become spaces); `fuzzycompletions` returns nothing. Most big-pharma EU MA vehicles have no LEI (Roche Registration, Novartis Europharm, Pfizer Europe MA EEIG…); parents go stale after mergers and spin-offs (Sandoz GmbH, lapsed, still names Novartis AG; Upjohn → Pfizer); former names find renamed entities (Genzyme Europe B.V. = Sanofi B.V.); homonyms abroad (Orion, Otsuka), opaque holdings (Chiesi → Valline, STADA → Nidda German Topco, Boehringer → C.H. Boehringer Sohn). Hence curated groups, GLEIF as provenance.
- Union Register holders (profiled 2026-09-28): every row has `MAH` {URI, Name, Address} (null for most nationally authorised rows); `MAH.URI` is one record per name and address, not per legal entity; the country is the address's last comma part in the local language (a small map in `R/orphan.R`, unknown → null); one "name" is an address (Deciphera); orphan-designation rows can name natural persons, so only Human rows are read.
- Internet Archive copies of the 2020 index (`web.archive.org/web/2020062…/https://www.whocc.no/atc_ddd_index/?code=L01XC|L01XE`): the only source for retired level-4 names; checked once by hand, never fetched at runtime.

## R conventions

## Trust baseline (with hosting; instead of ISO 27001 / SOC 2)
User wants credibility for a public site. ISO 27001 / SOC 2 certify organizations, not a static site with no backend or user data, so they are out of scope. Do instead:
- Security: Content-Security-Policy meta tag (GitHub Pages cannot set headers); no third-party scripts/fonts/trackers; Dependabot alerts + secret scanning + push protection; branch protection on `main`; CI actions pinned by SHA; `SECURITY.md`. Status of each: `docs/mvsp.md`.
- Privacy (GDPR): no cookies, no analytics; privacy note (GitHub logs IPs and page addresses, which hold the search, as host; offline mode stores only site data on the device; per-viewer conveniences in localStorage (theme, intro seen/closed, recently viewed lookups with a Clear in the search) stay on the device and are never sent).
- Accessibility: WCAG 2.2 AA target; axe-core in the headless check; manual keyboard pass.
- Intended use: informational only; not medical or legal advice; not a medical device; data may lag EMA.
- MVSP (mvsp.dev) self-assessment in `docs/mvsp.md` (control → status → evidence; review yearly): `SECURITY.md` with scope, safe harbor, GitHub private vulnerability reporting, fix within 90 days, notice within 72 h (1.1, 1.7, 3.4); data inventory (public regulatory data only, no personal data) + data-flow diagram (3.1, 3.2); Dependabot + `npm audit` gate (2.6); test forbidding `innerHTML`/`.html()` in `site/src` (2.5, 3.3); 2FA + branch protection (4.2); sub-processor list: GitHub (hosting, CI) (4.3); recovery = rebuild from repo + public sources (4.4). N/A: SSO, passwords, auth logging, physical access, pentest, training (no accounts, no backend, solo project).
- GitHub Pages cannot set response headers: no HSTS on custom domains, no `frame-ancestors`/X-Frame-Options (verified: jekyllrb.com on Pages sends none). Accepted risk (no logins or state-changing actions); alternatives are HSTS preload on the vrognas.com apex (Netlify) or hosting on Netlify with `_headers`.
